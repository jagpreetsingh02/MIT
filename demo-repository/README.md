# RootLine recording repository

Prepared real npm workspace scenario: storefront, checkout, and admin each depend on `@rootline/shared-http`, which depends on pinned axios and express releases. `package-lock.json` was generated by npm and records real installed dependency relationships. There is no application runtime or install script.

These deliberately old dependencies are analysis inputs. Use this folder for demonstrating dependency analysis, not as an application starter.

To prepare the GitHub recording:

1. Copy this folder into a separate Git repository and publish it to a public GitHub repository you control. Commit all manifests and the root lockfile. It has **not** been published automatically.
2. Paste that repository URL into RootLine and use the published commit SHA in the ref field for repeatable dependency input.
3. In Repository Map, select `apps/storefront`, `apps/checkout`, and `apps/admin`. Deselect the repository root and `packages/shared-http`; the shared package will be reached through the real workspace links.
4. Analyze, select the top vulnerable package, and click **Trace Ripple**. Inspect the source links and affected applications.

Local verification from the parent RootLine repository:

```sh
node --import tsx scripts/verify-controlled-demo.ts
```

The recorded verification checked 53 package versions, found findings on eight packages, and traced top-ranked axios through three paths to all three applications. See `../docs/verification/controlled-demo.json` for timestamped source evidence. Findings may evolve independently of the pinned dependency graph. Use RootLine’s clearly labeled offline synthetic demo if external APIs are unavailable during recording.
